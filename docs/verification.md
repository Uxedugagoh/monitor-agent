# Проверка проекта

В проекте есть автоматические тесты для основных модулей и набор ручных
сценариев для функций, которые зависят от обычного сеанса Windows.

<hr>

## Запуск автоматических тестов

Сначала соберите проект по инструкции из основного README. Затем выполните:

```powershell
ctest --test-dir out/build/release --output-on-failure
```

Проверка выполнялась на Windows x64 с MSVC в конфигурации Release.

<hr>

## Автоматические тесты

| Тест | Что проверяется |
|---|---|
| `activity_queue` | Порядок записей, лимит 100 элементов, закрытие очереди и конкурентный доступ |
| `activity_packet` | Структура JSON, Unicode, пакет из 10 записей и ожидание по таймеру |
| `http_sender` | HTTP-статусы, тайм-аут, недоступный сервер, повторы и сохранение очереди |
| `backup_store` | Запись, чтение, проверка формата, лимиты, блокировка и безопасная замена файла |
| `backup_lifecycle` | Восстановление при запуске и сохранение при остановке |
| `shutdown_monitor` | Завершение и отмена завершения сеанса Windows |
| `input_activity` | Фильтрация внедрённого ввода, граница 5 секунд и работа перехватчиков |
| `recovery_delivery` | Ошибка POST, резервная копия, повторный запуск и доставка в прежнем порядке |

Тестовые записи не содержат реальных данных пользователя. Сетевые тесты
работают через loopback-интерфейс и временный свободный порт.
