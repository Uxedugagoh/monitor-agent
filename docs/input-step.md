# Отслеживание активности ввода

За работу с клавиатурой и мышью отвечает
`src/collector/input_activity.cpp`. Модуль определяет только наличие недавнего
ввода и не сохраняет его содержимое.

<hr>

## Как отслеживается ввод

При запуске `InputActivityMonitor` создаёт отдельный поток с циклом сообщений
Windows. В этом потоке устанавливаются два низкоуровневых перехватчика:

<ul>
  <li><code>WH_KEYBOARD_LL</code> для клавиатуры;</li>
  <li><code>WH_MOUSE_LL</code> для мыши.</li>
</ul>

При подходящем событии сохраняется только текущее значение `GetTickCount64`.
Последняя отметка времени хранится в атомарной переменной, поэтому поток сбора
может читать её без мьютекса.

Перехватчики всегда вызывают `CallNextHookEx`. Они не блокируют и не изменяют
ввод пользователя.

<hr>

## Поле user_active

`src/collector/activity_collector.cpp` вызывает `hasRecentInput()` при каждом
замере.

Значение `user_active` равно:

- `true`, если после последнего принятого события прошло меньше 5000 мс;
- `false`, если прошло 5000 мс или больше;
- `false` до первого события после запуска агента.

События, которые произошли до запуска, определить нельзя.

<hr>

## Фильтрация искусственного ввода

События клавиатуры с флагами `LLKHF_INJECTED` и
`LLKHF_LOWER_IL_INJECTED` игнорируются. Для мыши таким же образом проверяются
флаги `LLMHF_INJECTED` и `LLMHF_LOWER_IL_INJECTED`.

Это позволяет не учитывать обычный ввод, созданный через Windows API. События
без этих флагов считаются активностью.

Такая фильтрация не гарантирует защиту от любой накрутки. Аппаратные имитаторы
и некоторые виртуальные устройства могут создавать события без этих флагов.
Агент не может достоверно отличить их от ввода человека, поэтому значение
`user_active` подтверждает только наличие принятого события, а не присутствие
человека за компьютером.

<hr>

## Какие данные не сохраняются

Агент не записывает:

- коды и названия клавиш;
- введённые символы;
- координаты мыши;
- историю событий ввода.

В записи активности попадает только логическое поле `user_active`.
