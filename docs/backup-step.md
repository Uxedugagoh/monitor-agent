# Резервное копирование и восстановление

За работу с резервной копией отвечает `src/storage/backup_store.cpp`. Файл
`backup.json` нужен для сохранения записей, которые не успели отправиться до
остановки агента.

<hr>

## Где находится backup.json

Путь считается от текущей рабочей папки, а не от папки с
`monitor_agent.exe`. Чтобы восстановить прежние данные, агент нужно повторно
запускать из той же папки.

Формат резервной копии отличается от HTTP-пакета:

```json
{
  "version": 1,
  "records": [
    {
      "time": "2026-09-23 12:00:00",
      "process_name": "editor.exe",
      "window_title": "Пример",
      "user_active": true
    }
  ]
}
```

Поле `version` позволяет проверять формат файла при загрузке.

<hr>

## Загрузка при запуске

`src/main.cpp` читает резервную копию до запуска потоков сбора и отправки.

При загрузке проверяются:

<ul>
  <li>корректность JSON;</li>
  <li>версия формата;</li>
  <li>наличие и типы всех полей;</li>
  <li>лимит в 100 записей;</li>
  <li>размер файла не более 16 МиБ.</li>
</ul>

Если файла нет, агент начинает работу с пустой очередью. Если файл повреждён,
агент выводит ошибку и завершает работу, не перезаписывая его.

Корректный файл после чтения сразу не удаляется. Это уменьшает риск потери
данных, если процесс аварийно завершится во время отправки.

<hr>

## Безопасное сохранение

Сохранение выполняется в несколько шагов:

1. Формируется полный JSON со снимком очереди.
2. Данные записываются в `backup.json.tmp`.
3. Запись принудительно сбрасывается на диск через `FlushFileBuffers`.
4. Временный файл закрывается.
5. `MoveFileExW` заменяет основной `backup.json`.

Старый файл не очищается перед записью нового. Если запись или замена не
удалась, предыдущая резервная копия остаётся доступной. Временный файл при
ошибке может остаться рядом для проверки.

<hr>

## Защита от одновременного запуска

При создании `BackupStore` открывается `backup.json.lock`. Файл удерживается
монопольно до завершения процесса.

Второй агент из той же рабочей папки не сможет открыть такую же резервную
копию. Сам lock-файл может остаться на диске после выхода: блокировка действует
только пока Windows-дескриптор открыт.

<hr>

## Сохранение при остановке

`src/runtime/shutdown_monitor.cpp` обрабатывает:

- `Ctrl+C`;
- закрытие окна консоли;
- выход из учётной записи;
- завершение Windows.

При обычной остановке завершается поток сбора, после чего `src/main.cpp`
сохраняет остаток очереди.

При закрытии консоли или завершении сеанса времени может быть мало. В этом
случае очередь сразу закрывается для новых записей, а её снимок сохраняется до
возврата из обработчика Windows.

Пустая очередь тоже записывается в файл как пустой массив. Это не позволяет
восстановить уже доставленные записи при следующем чистом запуске.
