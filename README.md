# Monitor Agent

Небольшой консольный агент мониторинга для Windows x64. Проект написан на
C++17 и собирается через CMake.

Агент раз в 5 секунд получает:

<ul>
  <li>имя процесса активного окна;</li>
  <li>заголовок активного окна;</li>
  <li>местное время замера;</li>
  <li>наличие ввода с клавиатуры или мыши за последние 5 секунд.</li>
</ul>

Записи временно хранятся в памяти и отправляются JSON-пакетами на локальный
HTTP-сервер. Если сервер недоступен, данные остаются в очереди и отправляются
повторно после восстановления соединения.

<hr>

## Как работает агент

1. При запуске агент читает `backup.json`, если файл существует.
2. Отдельный поток отслеживает события клавиатуры и мыши.
3. Поток сбора раз в 5 секунд получает активное окно и создаёт запись.
4. Запись добавляется в потокобезопасную очередь размером до 100 элементов.
5. Основной поток ждёт 10 записей или 30 секунд.
6. Готовый пакет преобразуется в JSON и отправляется методом `POST`.
7. Только ответ HTTP `2xx` удаляет записи из очереди.
8. При ошибке тот же пакет повторно отправляется через 5 секунд.
9. При остановке оставшиеся записи сохраняются в `backup.json`.

Сетевой запрос выполняется не в потоке сбора. Поэтому медленный или
недоступный сервер не останавливает получение новых замеров, пока в очереди
есть свободное место.

## Сборка

Понадобятся:

<ul>
  <li>Windows x64;</li>
  <li>Visual Studio или Build Tools с компонентами C++ и Windows SDK;</li>
  <li>CMake 3.20 или новее;</li>
  <li>Ninja.</li>
</ul>

Команды нужно выполнять из корня проекта в Developer PowerShell for Visual
Studio или x64 Native Tools Command Prompt:

```powershell
cmake -S . -B out/build/release -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TRY_COMPILE_CONFIGURATION=Release
cmake --build out/build/release
ctest --test-dir out/build/release --output-on-failure
```

Параметр `CMAKE_TRY_COMPILE_CONFIGURATION=Release` включает конфигурацию
Release и для проверочных сборок CMake. Зависимости уже добавлены в
`third_party`, поэтому загружать их во время сборки не нужно.

<hr>

## Запуск

Сначала запустите демонстрационный сервер:

```powershell
.\out\build\release\demo_server.exe
```

Во втором терминале запустите агент:

```powershell
.\out\build\release\monitor_agent.exe
```

Сервер принимает запросы только по адресу `http://127.0.0.1:8080/`, печатает
полученный JSON и отвечает кодом `204 No Content`. Первый пакет обычно
появляется примерно через 30 секунд.

Параметров командной строки нет. Адрес сервера и интервалы сейчас заданы в
коде.

<hr>

## Сбор активности

Имя процесса и заголовок берутся у окна, которое находится на переднем плане.
Строки Windows преобразуются в UTF-8. Если окно или процесс недоступны,
соответствующее поле может быть пустым.

Для клавиатуры и мыши используются низкоуровневые перехватчики Windows. Агент
хранит только время последнего события. Коды клавиш, введённый текст,
координаты мыши и история ввода не сохраняются.

События с флагом `INJECTED` игнорируются. Поле `user_active` равно `true`, если
после последнего принятого события прошло менее 5 секунд. До первого события
после запуска значение равно `false`.

Фильтрация исключает обычные программно сгенерированные события, помеченные
Windows как внедрённые. Она не гарантирует защиту от любой накрутки:
аппаратные имитаторы и некоторые виртуальные устройства могут создавать
события без этих флагов, которые агент учитывает как активность. Поэтому
`user_active` не доказывает присутствие человека.

<hr>

## Очередь и отправка

Очередь хранит не более 100 записей. При заполнении новые замеры пропускаются,
а их количество выводится при завершении агента.

Для отправки копируются до 10 первых записей. По таймеру отправляется и неполный пакет.
HTTP-запрос выполняется без
удержания мьютекса очереди. После успешного ответа записи удаляются. При
сетевой ошибке или ответе не из диапазона `2xx` записи остаются в очереди.

Тайм-ауты подключения, чтения и записи равны 2 секундам каждый. Это отдельные
тайм-ауты операций, а не общий лимит времени на весь запрос.

<hr>

## Формат JSON

Агент отправляет `POST /` с заголовком `Content-Type: application/json`:

```json
{
  "agent_id": "DESKTOP-EXAMPLE",
  "timestamp": 1790000000,
  "payload": [
    {
      "time": "2026-09-23 12:00:00",
      "process_name": "notepad.exe",
      "window_title": "Заметки — Блокнот",
      "user_active": true
    }
  ]
}
```

- `agent_id` — имя компьютера;
- `timestamp` — время формирования пакета в секундах Unix;
- `time` — местное время отдельного замера;
- `payload` — список записей активности.

## Остановка и восстановление

Для обычной остановки нажмите `Ctrl+C`. Также обрабатываются закрытие консоли,
выход из учётной записи и завершение Windows.

Оставшиеся записи сохраняются в `backup.json` в текущей рабочей папке. При
следующем запуске из той же папки агент восстановит их и продолжит отправку.

Сначала данные записываются в `backup.json.tmp`, затем временный файл заменяет
основной. `backup.json.lock` не позволяет двум агентам одновременно работать с
одной резервной копией.

Повреждённый `backup.json` не перезаписывается: агент выводит ошибку и завершает
работу. Размер файла ограничен 16 МБ, а число записей — размером очереди.

## Проверка

В проекте есть 8 автоматических тестов. Они проверяют:

- очередь, лимит и конкурентный доступ;
- структуру JSON и работу с Unicode;
- HTTP-статусы, тайм-ауты и повторные попытки;
- сохранение и чтение `backup.json`;
- восстановление данных после перезапуска;
- обработку завершения Windows;
- фильтрацию событий ввода;
- доставку восстановленных записей в исходном порядке.

Подробности об автоматических тестах находятся в
[docs/verification.md](docs/verification.md).

## Основные файлы

| Файл | Назначение |
|---|---|
| `src/main.cpp` | Запуск компонентов, поток сбора, восстановление и финальное сохранение |
| `src/collector/activity_collector.cpp` | Получение времени, процесса и заголовка активного окна через Win32 API |
| `src/collector/input_activity.cpp` | Отслеживание клавиатуры и мыши без сохранения содержимого ввода |
| `include/buffer/activity_queue.h` | Потокобезопасная очередь, выбор группы записей и подтверждение отправки |
| `src/serialization/activity_packet.cpp` | Преобразование записей в JSON требуемого формата |
| `src/network/http_sender.cpp` | HTTP POST, тайм-ауты, проверка ответа и повторные попытки |
| `src/storage/backup_store.cpp` | Чтение, проверка и безопасная замена `backup.json` |
| `src/runtime/shutdown_monitor.cpp` | Обработка `Ctrl+C`, закрытия консоли и завершения сеанса Windows |
| `tools/demo_server.cpp` | Локальный сервер для проверки отправляемых пакетов |
| `tests/` | Автоматические проверки отдельных модулей и полного восстановления |
| `CMakeLists.txt` | Настройка сборки приложений, библиотек и тестов |
